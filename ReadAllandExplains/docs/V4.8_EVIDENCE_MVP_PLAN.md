# ReadAllandExplains 4.8 Evidence MVP 计划

> 状态：执行中  
> 建立日期：2026-08-09  
> 目标版本：`v4.8.0-preview.1`  
> 答辩目标日期：2026-08-11  
> 文档职责：记录 4.8 MVP 的产品判断、证据标准、实现边界、验收方式和 Git 回滚机制。代码、Git 和真实测试结果优先于本文。

## 1. 产品定义

ReadAllandExplains 不是简单的 UE 文档导出器，而是面向 UE 技术美术资产的 **AI Context Compiler / UE 资产证据编译器**。

核心链路：

1. 插件从 UE 获取权威事实，生成可验证的 Context Pack。
2. MCP 围绕当前问题定位并返回最小必要证据。
3. Skill 组织“概览、定位、取证、判断、解释或补拍”的分析流程。
4. AI 只在证据范围内解释，证据不足时输出明确缺口。
5. SyncLive 经用户授权回 UE 定向补拍，再基于新证据续答。

一句话定义：

> 把 UE 中复杂、分散、难读取的资产事实，稳定编译成 AI 可按需查询、验证、追溯和持续补全的证据结构。

## 2. 4.7 的现状与 4.8 的质变

### 4.7 已经具备

- Blueprint、Material、Material Function、Niagara、Renderer、曲线、Custom HLSL、UEnum、DataAsset 等多类型资产快照。
- Markdown 与 JSON 双视图。
- Schema 2 统一图 IR。
- Context Pack、Metadata、Index、Manifest、内容指纹和原子发布。
- 只读 MCP、分析 Skill、CodeBuddy/WorkBuddy 接入。
- 证据不足时，经授权定向补拍并续答的闭环。
- Golden Pack 和严格完整性门禁。

### 4.7 的核心问题

4.7 能持续查询和补拍，但查询过程仍偏向“读取一个完整文件后再理解”：

- 大 Graph 不能先定位再取最小子图。
- Readable 文档缺少稳定章节索引。
- 节点、Pin、参数、输出与文档位置之间缺少统一寻址目录。
- 超过上下文预算后，分页只能机械截断，无法保证返回的是与问题相关的计算闭包。
- Base Pack 与后续 Delta Pack 尚未形成统一资产视图。

### 4.8 的目标

4.8 的质变不是“第一次可以循环补拍”，而是：

> 从“可续答的多 Pack 链路”升级为“按问题定位最小证据，并能把后续证据持续接回同一上下文”。

本次答辩前 MVP 聚焦前半段：**可寻址、可定位、可切片、可回链**。

## 3. 证据标准

证据标准不是从字段列表出发，而是从 AI 如何可靠回答 UE 资产问题反推。标准必须同时满足以下条件。

| 标准 | 要求 | 解决的问题 |
|---|---|---|
| 权威性 | UE 插件导出的 Raw Facts 是唯一事实源 | 防止 AI 将推断冒充引擎事实 |
| 可寻址 | 资产、Graph、Node、Pin、参数、输出具有稳定标识 | 不再依赖名称或行号猜测位置 |
| 可追溯 | 结论可回链到 Pack、资产、Graph、Node、Pin 和 JSON/Readable 位置 | 让关键结论可复核 |
| 可切片 | 能按目标、方向、跳数和字符预算获取最小闭包 | 大图不再一次性塞入上下文 |
| 可分层 | 原始事实、程序派生视图、AI 语义彼此分离 | 防止语义标注污染原始数据 |
| 可演进 | Schema、来源、指纹、状态和兼容策略明确 | 支持持续导出、补拍和版本升级 |

三层数据模型：

### Raw Facts

由 UE 插件直接导出，不允许 AI 改写。包括资产身份、节点、Pin、连线、参数、依赖、Renderer 配置、曲线 Key、材质设置等。

### Derived Views

由确定性程序从 Raw Facts 生成。包括 `graphIndex`、Compact Graph、最小子图、SSA Slice、依赖闭包、Coverage 和 Diff。派生视图可以重建，不反向覆盖 Raw Facts。

### Semantic Overlay

保存用途解释、参数语义、风险标签、美术建议、置信度、模型版本和人工修正。语义不确定时允许 `unknown`，不得写回原始事实。

核心边界：

> AI 可以解释 UE，但不能篡改 UE 事实。

## 4. MVP 范围

### P0：本轮必须完成

1. `graphIndex` 最小可用版。
2. 目标定位能力。
3. 向上游最小子图读取能力。
4. Readable 稳定章节索引与按章节读取能力。
5. 证据回链与预算截断诊断。
6. 4.7 Context Pack 向后兼容。
7. MCP 契约测试与 Golden 基线不回退。

### MVP 查询接口

| 接口 | 职责 |
|---|---|
| `get_asset_outline` | 返回资产、Graph、Readable 章节和 Coverage 概览 |
| `locate_graph_target` | 按节点类型、名称、参数、Pin、输出或函数定位候选 |
| `get_graph_subgraph` | 以目标为中心，按方向、跳数和预算返回最小子图 |
| `get_readable_sections` | 返回章节 ID、标题、摘要、字符量和证据位置 |
| `get_readable_section` | 按稳定章节 ID 精确读取正文 |

分页保留为兜底，但不是主能力。主路径必须是：

```text
问题
  → 资产概览
  → 目标定位
  → 最小子图或章节
  → 预算与完整性判断
  → 带 Evidence 的解释
  → 证据不足时申请补拍
```

### `graphIndex` 最小字段

```json
{
  "schemaVersion": 1,
  "graphs": [
    {
      "graphId": "stable-graph-id",
      "nodeCount": 0,
      "edgeCount": 0,
      "entryPoints": [],
      "searchIndex": []
    }
  ]
}
```

每个索引项至少能够稳定回链至：

```text
assetId → graphId → nodeId / pinId → JSON path → Readable sectionId（若存在）
```

### Readable MVP 章节

优先支持以下稳定章节类型，实际标题可以随资产类型变化，但 `sectionId` 不依赖显示标题：

- 资产身份与摘要
- 参数与配置
- Graph / 节点结构
- Renderer / 输出
- 依赖与引用
- 诊断与 Coverage

## 5. 答辩 Golden Demo

唯一英雄资产：`FX_Syst_Waterfall_FXTex`。

固定问题：

1. 该 Niagara System 包含哪些 Emitter、Renderer 和材质引用？
2. 某个 Renderer 的关键视觉属性由哪条材质参数或节点链驱动？
3. 当前快照能确认什么、不能确认什么，缺少哪些证据？

演示目标：

- 4.7：读取较大文档或完整资产后回答。
- 4.8：先展示 Outline，再定位目标，只取最小证据子图，最后附 Evidence 回链。
- 可选高潮：故意缺失依赖，系统明确指出缺口，经授权补拍后续答。

MVP 不追求覆盖所有 UE 资产类型，只保证 Niagara、Material、Material Function 的英雄链路可稳定演示。

## 6. 兼容与安全边界

- `v4.7.0` 保持冻结，不在发布分支直接开发。
- 新能力优先采用增量字段或侧车派生数据，保留现有 Raw JSON 和完整 Readable。
- 旧 Pack 没有 `graphIndex` 或章节索引时，MCP 必须明确降级，不得把缺失数据伪装成空结果。
- 新索引生成失败不能产生看似完整但不可验证的 Pack。
- `complete`、Manifest、Metadata、Index、原子发布等 4.7 严格语义不得弱化。
- Evidence 必须引用真实存在的文件和结构位置。
- 子图被跳数、节点数或字符预算截断时，响应必须返回 `truncated` 和原因。
- 静态快照不能证明运行时行为；运行时状态仍需明确标记为未知或通过后续观测补充。

## 7. 明确延后

以下内容不进入答辩前 MVP：

- 通用 Base + Delta 自动联合查询。
- 全资产类型通用 Graph Query DSL。
- 蓝图业务逻辑深度解析。
- 放置实例和组件 Override 的完整运行态值。
- 通用语义 Diff、TA Audit 和反向导入。
- 真实移动端 / 双端产品化。
- 大规模数据库与跨项目资产治理平台。

## 8. 验收标准

### 功能验收

- 能列出目标资产的 Graph 与 Readable 章节概览。
- 能通过名称、类型、参数、Pin 或输出定位候选节点。
- 能从目标节点向上游返回有边界的最小子图。
- 每个关键结果带稳定 Evidence。
- 超预算或证据缺失时给出明确诊断。
- 旧 4.7 Pack 仍能被现有查询接口正常读取。

### 自动化门禁

- `git diff --check` 通过。
- MCP 契约测试全部通过。
- Golden Python 测试全部通过。
- 新增查询接口具备成功、未找到、歧义、无索引、预算截断和旧 Pack 降级测试。
- 涉及 C++ 或导出结构后，必须完成 UE 5.7 Win64 编译。
- 涉及真实 Graph 数据后，必须生成并验证真实 Context Pack。

### 演示验收

同一个问题能够清楚展示 4.7 与 4.8 的差异：

- 读取范围更小。
- 定位过程可见。
- 关键结论有证据回链。
- 不确定性和缺口表达更可靠。

## 10. 实施顺序

1. 固化文档和 Git 回滚点。
2. 先在 MCP 对现有 Raw JSON 构建确定性派生 Outline、章节和 Graph 查询，快速验证查询协议。
3. 用测试样本稳定接口、Evidence 和错误语义。
4. 再将成熟的索引字段前移到 UE 插件导出端，生成原生 `graphIndex` 与章节元数据。
5. Skill 固化查询编排，不复制事实或缓存未经验证的结论。
6. 使用英雄资产生成新 Pack，完成 Before / After 演示。

这个顺序遵循“先验证最小可行协议，再改动 UE 导出契约”，既能在答辩前获得可见效果，也能降低 C++ 编译和真实资产回归带来的时间风险。

### 2026-08-09 CP4 双客户端人工验收结果

- Trans 与 CodeBuddy 在互不参考的前提下各自新建会话，使用同一基准 Pack 与同一套问题独立执行三轮测试，全部通过。详见 `docs/V4.8_MVP_ACCEPTANCE_REPORT.md`。
- 两端结果逐字段一致：Pack 指纹、4 张 Graph 的完整 `graph_id` 与节点连线数、7 个稳定 `section_id` 与字符量、章节行与字符范围、4 项定位候选及 `match_type`、唯一 `node_id`、子图 6 节点 / 5 连线 / 6016 字符、全部 `pin_id`、截断态 1 节点 / 0 连线 / 1954 字符、`truncation_reasons=[max_nodes]`、边界连线 `/graphs/1/links/45`、`omitted_node_count=5`。
- 由此确立答辩核心论据：4.8 返回的是可被第三方复核的确定性事实，而不是模型每次即兴生成的近似解释。确定性可复核，解释不可复核，这是证据标准与“接一个大模型”的根本区别。
- 三处自洽性交叉验证成立：截断原因与设定的 `max_nodes` 严格对应；`omitted_node_count=5` 与完整子图 6 节点相减吻合；边界连线正是完整子图的最后一跳。
- 接入故障根因已确认并归档：真正的启动源是 CodeBuddy 插件市场注册表 `known_marketplaces.json`，它会覆盖工作区 `.mcp.json` 与 `config/mcporter.json`。排查必须按“注册表 → 实际进程命令行 → `READALL_EXPORT_ROOT` → 工作区配置”的优先级进行，且切换后需完全重启客户端并新建会话。
- 正向信号：接口缺失期间两端都主动停止并报告缺失，未回退到 `get_asset_summary` 等旧接口伪造结果，禁止静默降级的约束有效。
- 顺带发现英雄资产命名不一致（`SampleFXTex1.FXTex1` 与 `SampleFXTex.FXTex2/3`），可作为“证据级读取能发现肉眼易忽略问题”的演示素材；但证据只能确认 Pin 标题差异，是否影响行为需回 UE 确认。
- 字符口径统一：`6,016` 指子图数据本身，`13,757` 指含完整响应信封，两者不可混用。

### 2026-08-09 SyncLive 补拍闭环验证通过

- 补拍是唯一有真实副作用的能力，按“预检 → 复述计划 → 等许可 → 执行”验证，预检阶段正确停手等待授权，未擅自提交。
- 预检对“SyncLive 是否可受理”回答“未能确认”，并说明缺少独立健康检查接口，拒绝用 `list_context_packs` 冒充服务状态证明，边界意识正确。
