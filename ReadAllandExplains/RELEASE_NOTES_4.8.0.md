# ReadAllandExplains 4.8.0

UE 资产证据编译器。把蓝图、材质和 Niagara 资产编译成可被 AI 渐进式查询的静态证据快照，每条结论都能回指到快照中的确切位置。

## 本版本的主线变化

### 原生索引由导出器写入

4.7 及之前，图索引是 MCP 在内存中派生的：每次读取都要重新枚举一遍全部图、节点和引脚，并发出 `GRAPH_INDEX_DERIVED` 警告说明这份索引不是 UE 原生字段。

4.8 把索引构建移进导出器。`metadata.graphIndex` 现在是落盘的一等字段，包含根级汇总与每图的 `entryPoints` / `searchIndex`，每项携带 `jsonPointer`。MCP 读取时先校验它与所描述的图是否一致，一致则报 `native_metadata_graph_index` 且不再发出派生警告。

索引与实际图数据不一致时自动回退到派生路径。一份过期的索引比没有索引更危险，因为调用方会把它当证据引用。

### Niagara Custom HLSL 正文成为一等证据

此前 Custom HLSL 节点只导出结构，不导出源码，分析时必须回到编辑器打开节点才能看到正文。现在 `sourceCode` 随节点一起落盘，可直接被引用和检索。

### 渐进式查询

`get_asset_outline` 先给规模概览，`locate_graph_target` 定位目标，`get_graph_subgraph` 按预算切片，`get_readable_sections` 按稳定 section_id 取正文。大型资产不需要整包读入。

本次验证的 Niagara 系统有 20 张图、767 节点、2951 引脚，其中单张模块图 238 节点；蓝图侧 `UserConstructionScript` 单图 225 节点，是同资产其余六张图总和的七倍多。这类资产整图读入会直接耗尽上下文预算，定位再切片是唯一可行路径。

## 验证情况

### 契约与回归

契约测试 57 项、Golden 回归 22 项全部通过。

### 原生索引覆盖度

对实际导出的 Pack 全量审计：84 个 metadata 文件中 63 个带图，**63 个全部携带经校验的原生索引，覆盖度 100%**。审计逐项比对落盘 `graphIndex` 与同文件 graphs 的图标识、节点数、引脚数、连线数、`jsonPointer` 与根级汇总。

审计器本身做了阴性对照：篡改计数与指针后必须失败并指名问题字段。一个不会失败的检查不构成证据。

### 双部署读取确定性

同一份不可变 Pack，由两个独立部署、独立进程、独立工作目录分别读取，比对 5 组查询的 **63 个叶字段，零分歧**。

```text
A  工作区部署        C:\...\ReadAllandExplains_4.8.0_mvp\...
B  UE 项目安装部署   D:\UE5\Trans\plugins\ReadAllandExplains\...
```

比对器同样有阴性对照：篡改两个字段后精确命中两处并返回 FAIL。

详见 [CP7_DUAL_ENDPOINT_RESULT.md](docs/CP7_DUAL_ENDPOINT_RESULT.md)，原始采集结果在 `docs/evidence/`。

## 本版本明确不主张的结论

以下边界如实列出，以免被误读为更强的保证。

**双部署一致不等于两套独立实现互相印证。** 两个端点运行同一份源码，SHA256 已确认相同。这轮排除的是部署漂移、进程状态残留和配置相关行为差异，不构成跨实现的交叉验证。真正的交叉验证需要第二套独立实现，本项目没有。

**读取一致不等于导出正确。** 若导出阶段漏采了某个节点，两个端点会一致地漏掉同一个。本版本验证读取确定性与索引自洽性，不证明导出对 UE 内部状态的完整覆盖。

**静态快照不能证明运行时行为。** GPU 逐帧结果、动态 Render Target 内容、PIE 时序、参数运行时最终值均不在快照能力范围内，须在编辑器中验证。

**覆盖度数字绑定具体 Pack。** 100% 是对本次审计的 84 资产 Pack 而言。更大规模或含异常资产的 Pack 需要重新实跑审计，不能沿用此结论。

## 一个值得记录的缺陷

`locate_graph_target` 曾硬编码 `graph_index_source` 为 `derived_metadata_graphs`，从未做过实际判断。结果是同一份原生索引 Pack 上，`get_asset_outline` 报原生而 `locate_graph_target` 报派生，两个工具自相矛盾。

契约 54 项、Golden 22 项、parity 1619 资产全绿都没有发现它，因为没有任何一条测试断言过该字段。它是在双端比对中被暴露的。

已修复，并补充 3 条回归测试锁定该契约。教训是既有的那条：**测试未覆盖的契约变更是静默回归的常见来源。**

原先的 parity 脚本也存在同类问题——它用 Python 重建一份索引再与图自比，导出器真正写入磁盘的内容从未被读取，因此在导出器写错时不会失败。本版本已替换为直接校验落盘 `graphIndex` 的审计器。
